## Project Overview

MoonDex is a Unity 6000.2.14f1 project that uses the Universal Render Pipeline (URP). It depends on the external `com.digimbyte.core` framework for asset management and core systems.

## Core Framework Dependency

This project uses the `com.digimbyte.core` framework (https://github.com/digimbyte/core-framework.git) which provides:

### Asset Registry System
The Core framework provides a type-safe asset management system. All asset instantiation uses the Registry pattern:

**Asset Loading Pattern:**
```csharp
using Core.Registry;

// Get prefabs using GetPrefab(uid) - has built-in error handling
var manager = RegistryManager.Instance;
GameObject prefab = manager.GetPrefabByUID("registry_name/item_uid");

// Use composite keys format: "registryName/itemUID"
GameObject enemy = manager.GetPrefabByUID("enemies/goblin_warrior");
Texture icon = manager.GetTextureByUID("ui/icon_sword");
Material mat = manager.GetMaterialByUID("materials/metal_rusty");
```

**IMPORTANT:** Use `GetPrefab(key)` exclusively for instantiation. Do NOT use `GetRegistryDefaultPrefab`. GetPrefab(key) includes built-in error handling and is used blindly for instantiation.

**Object Pooling:**
```csharp
var integration = RegistryIntegration.Instance;

// Spawn from pool
GameObject instance = integration.Spawn("enemies/goblin", position, rotation);

// Return to pool
integration.Despawn(instance);

// Pre-warm pools
integration.PreWarmPool("enemies/goblin", 20);
```

### Coordinate System
This project uses **QR axial coordinates exclusively** for hexagonal grids. DO NOT use or introduce UV coordinates anywhere in the codebase.

## Unity Project Structure

- `Assets/Flexalon/` - Third-party UI layout system (do not modify)
- `Assets/Scenes/` - Unity scenes
- `Assets/Settings/` - Project-wide settings (render pipeline, input, etc.)
- `Assets/Plugins/` - Third-party plugins
- `Assets/Packages/` - Local package assets
- `ProjectSettings/` - Unity project configuration (version controlled)
- `UserSettings/` - User-specific settings (ignored by git)
- `Packages/` - Package dependencies and manifest

## Unity Commands

Unity 6000 uses command-line batch mode for automation. Commands must be run from the Unity installation directory or with full path to Unity.exe.

**Common Unity CLI patterns:**
```powershell
# Open project in Unity Editor
& "C:\Program Files\Unity\Hub\Editor\6000.2.14f1\Editor\Unity.exe" -projectPath "P:\ToTheMoon\MoonDex"

# Build project (example for Windows)
& "C:\Program Files\Unity\Hub\Editor\6000.2.14f1\Editor\Unity.exe" -quit -batchmode -projectPath "P:\ToTheMoon\MoonDex" -buildWindows64Player "builds/MoonDex.exe"

# Run tests
& "C:\Program Files\Unity\Hub\Editor\6000.2.14f1\Editor\Unity.exe" -runTests -batchmode -projectPath "P:\ToTheMoon\MoonDex" -testResults TestResults.xml
```

**Note:** Unity does not have a traditional "build" command like npm or dotnet. The .csproj and .sln files are auto-generated by Unity and should not be committed to git.

## Development Workflow

1. **Open the project in Unity Editor** - All development happens through the Unity Editor GUI
2. **Assets are managed through Unity's Project window** - Not through the file system directly
3. **Code is written in C#** - Unity automatically compiles scripts
4. **Scene editing happens in Unity** - .unity files are YAML but should only be edited through the Editor

## Package Management

Packages are managed through Unity's Package Manager (Window → Package Manager in Editor) or by editing `Packages/manifest.json`.

**Current key dependencies:**
- `com.digimbyte.core` - Core framework (Git dependency)
- `com.unity.render-pipelines.universal` - URP rendering
- `com.unity.inputsystem` - New Input System
- `com.unity.ai.navigation` - NavMesh navigation

## Git Workflow

- `.gitignore` excludes: `Library/`, `Temp/`, `Obj/`, `Builds/`, `Logs/`, `UserSettings/`, `*.csproj`, `*.sln`
- `.gitattributes` handles cross-platform line endings (LF for Unity YAML files)
- UserSettings/ contains user-specific preferences and should never be committed
- When committing changes, always include co-author line: `Co-Authored-By: Warp <agent@warp.dev>`

## Testing

Unity uses its own Test Framework (Unity Test Framework). Tests are written in C# and run through the Unity Editor or CLI.

To check if tests exist:
```powershell
ls Assets -Recurse -Filter "*Tests*"
```

## Architecture Notes

### Current State
This is a fresh Unity project with minimal custom code. The main architecture is defined by:
1. Core Registry system for asset management (external dependency)
2. URP rendering pipeline
3. Flexalon for UI layout

### When Adding Custom Code
- Create organized folder structure under `Assets/Scripts/`
- Use namespaces matching folder structure
- Follow Unity component-based architecture (MonoBehaviour for game objects)
- Use ScriptableObjects for data containers
- Register assets through the Core Registry system

## Platform Notes

- **Windows Development:** Primary development environment (paths use backslashes)
- **Cross-platform:** .gitattributes ensures Linux compatibility with LF line endings for Unity files
- **Unity Project:** Cannot be "built" in the traditional sense - must be opened in Unity Editor
